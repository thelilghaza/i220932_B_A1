# Part 21 — Traceability Matrix

In production MLOps, every deployed artifact in staging or production must be strictly traceable back to its originating Pull Request, Merge Commit, and Git Tag. This document details the complete end-to-end traceability chain for releases `1.0.0` and `1.1.0`.

---

## 1. Traceability Architecture

```
+--------------------------+
|   Pull Request (PR #1/2) |
+-------------+------------+
              |
              v (Code Review + Status Checks Pass)
+-------------+------------+
|     Merge Commit SHA     |
+-------------+------------+
              |
              v (Tag Created & Pushed)
+-------------+------------+
|         Git Tag          |
+-------------+------------+
              |
              v (GitHub Actions Release Workflow)
+-------------+------------+
|     Docker Image Tag     |
+-------------+------------+
              |
              v (Immutable Digest Generated by GHCR)
+-------------+------------+
|    Docker Image Digest   |
+--------------------------+
```

## 4. OCI Label Metadata Traceability (Part 23)
The following labels are embedded inside the image layers:
```bash
docker inspect student-ml-api:1.0.0 --format '{{json .Config.Labels}}'
```
Output:
```json
{
  "org.opencontainers.image.title": "student-ml-api",
  "org.opencontainers.image.description": "ML inference service for student prediction API",
  "org.opencontainers.image.version": "1.0.0",
  "org.opencontainers.image.revision": "6f59156",
  "org.opencontainers.image.authors": "thelilghaza",
  "org.opencontainers.image.source": "https://github.com/thelilghaza/i220932_B_A1"
}
```
This enables any auditor to pull the image and determine the exact repository, commit, and version that created it without accessing source code.
